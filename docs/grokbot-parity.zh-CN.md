# Grok Bot 功能对齐清单

本项目按 README 所引用的 Grok Bot 团队助手工作流实现兼容体验。参考资料为 [功能介绍](https://www.mindstudio.ai/blog/grok-bot-ai-agent-fleet) 与 [团队搭建介绍](https://www.mindstudio.ai/blog/how-to-build-grokbot-agent-team)，属于第三方介绍；除下述调度资料外，其余能力尚未按完整官方规格或登录后的行为逐项验收，因此不能据此宣称与某个 Grok Bot 版本完全一致。

2026-10-25 已针对调度核对官方 [多个 Bot 同时工作](https://docs.x.ai/grok-bot#can-several-bots-work-at-the-same-time)、[异步交接与纠正](https://docs.x.ai/grok-bot/chat-and-collaboration#let-bots-hand-work-off) 和 [v0.59.0 消息优先级](https://x.ai/changelog/bot#v0.59.0)。本项目据此实现不同 Bot 同时执行、同 Bot 跨会话共用执行名额、异步委派及排队用户消息优先；任务进行中的用户消息交给在途工作的 Bot，由它判断是重定向当前任务还是另一个新请求。四名独立协作者上限是本项目的自动分工策略，并非 Grok Bot 官方额度。官方资料未说明所有用户新任务是否严格 FIFO，也未据登录后运行结果逐项验收。此处只说明已核实的调度范围，不代表整体功能完全一致。

本清单记录已有能力，不代表没有功能缺口。当前已确认的链路问题、未实现能力及优先级见 [2026-10-24 功能差距审计](grokbot-gap-audit.zh-CN.md)。

投入与范围按用户措辞执行：快查聚焦决定性问题，深入核查覆盖关键证据与反例，局部修改不扩大范围，可用初稿须有完整内容而非提纲。要求随分工传递，不以人数、报告长度或模型设置变化冒充质量。本轮尝试重新读取官方协作文档时连接超时，未取得新官方证据；以上属于本项目设计，不能据此宣称已对齐 Grok Bot 的新行为。

后续迭代以 [提示词场景表](../prompts/README.md) 为验收入口：先记录实际失败的输入、预期行为与证据，再修改对应规则，同时删除冲突或重复要求；检查功能开关、角色模板和动态注入段，运行相关拼接测试，最后用真实模型复测失败场景。静态检查或单元测试通过不能替代真实模型行为验证。每轮完成具体改进，不因“持续迭代”自动创建例行任务；未构建和重启时，运行服务仍可能使用旧提示词。

审计前七项已实现，具体限制见[附件、回执与历史说明](files-and-history.zh-CN.md)和[共享账号、事件接入与可靠恢复](accounts-events-recovery.zh-CN.md)。社交测试采用本地模拟平台，不能替代真实账号资格及权限验收。

## 配置事件任务

先在「设置 → 连接与密钥」保存签名密钥，然后在「设置 → 例行任务」选择平台事件，填写事件类型、密钥名称及可选筛选。例：

```json
{
  "kind": "event",
  "source": "github",
  "event": "push",
  "filters": {
    "/repository/full_name": "owner/repo",
    "/ref": "refs/heads/main"
  },
  "signingSecret": "GITHUB_WEBHOOK_SECRET"
}
```

GitHub 的 Secret 使用同一密钥值，事件选 push。Slack 的 `signingSecret` 对应 App 的 Signing Secret；事件如 `message`，频道筛选可使用 `{"/event/channel":"C012345"}`。Teams Workflows 可直接 POST JSON，默认事件类型为 `message`；若设置签名密钥，调用方还需发送 `X-Teambot-Signature-256: sha256=<body 的 HMAC-SHA256 十六进制值>`。

通用 webhook 可带 `Idempotency-Key` 请求头。没有去重键的不同调用分别排队。事件请求体最多 256 KiB，交给模型的事件数据会截取到 8000 字符并标注为不可信输入。自动化保存成功仅表示本地配置成功；在「配置与测试」区分本地诊断、订阅和平台到达，完成外部平台配置并核对运行记录后才算打通端到端事件链路。

## 验证方式

```sh
cargo test
cargo clippy --all-targets -- -D warnings
cargo build
node dev/e2e.mjs
node dev/multi-mention.e2e.mjs
node dev/handoff.e2e.mjs
node dev/local.e2e.mjs
node dev/integrations.e2e.mjs
node dev/channels.e2e.mjs
node dev/attachments.e2e.mjs
npm ci --prefix dev
# 首次使用：在 dev 目录执行 npx playwright install chromium
node dev/ui.e2e.mjs
# 或使用已安装的 Chrome：
DOTBOT_CHROME=/opt/google/chrome/chrome node dev/ui.e2e.mjs
```

协议检查使用模拟 Claude CLI；浏览器检查使用一个真实浏览器、一个上下文和一个页面，Bot 浏览器由 MCP 测试服务器替代，不调用收费模型或发送外部消息。截图输出到 `test-results/`，成功或失败都会关闭测试创建的浏览器和服务。
