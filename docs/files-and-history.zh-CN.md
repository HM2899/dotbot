# 附件、消息回执与完整历史

本轮落实功能差距审计的前四项：社交平台附件、失败与取消回执、完整历史及未读、网页通用文件上传。管理入口仍在设置中；本机协同保持终端和文件能力，不增加本机图形界面。

## 网页上传与协作

Bot 单聊和群聊均可点击附件按钮、拖入文件或粘贴图片。每条消息最多 8 个文件，每个最多 25 MiB，总计最多 50 MiB。上传中的文件显示状态；失败可重试、移除，发送失败保留草稿。切换会话分别保存当前页面的文字和附件草稿，避免把文件误发到其他聊天。草稿不承诺跨刷新恢复。

上传接口需要网页登录凭据；文件引用只授权给上传所在会话。委派工具 `message_bot` 或带初始任务的 `create_bot` 省略 `files` 时，自动继承当前任务的附件及多级委派的输入；显式传入附件列表时仅分享选中项，`files: []` 表示不分享。明确引用刚才上传的附件时可从本会话已发送消息解析，未发送的上传和其他会话文件不会自动带入。协作者获得授权后才能接收；产物和协作结果可返回原会话及原社交渠道。文件保留原始字节、原文件名和类型，网页提供预览或下载。上传本身不是已发送消息，不增加未读。

模型读取方式：

- PNG、JPEG、GIF、WebP 和 PDF 通过模型的原生内容输入（Anthropic 图片/文档块，或 OpenAI image_url/file）。过大图片会生成有界缩略预览，原附件不变；原生输入总预算为 25 MiB，无法预览时会明确告诉模型，不能声称看过内容。
- 文本、JSON、XML、YAML 提供合计约 64 KB 的预览；截断时明确标注，附件内容作为不可信任务数据处理。
- Office、ZIP、音视频及其他二进制文件保留文件引用。启用本机终端时用 `local_receive_file`，或启用 Docker 电脑后用 `receive_file` 接收处理。两者均关闭时不会假装已经读取内容。接收音频不等于自动转写。

文件下载需要登录；响应带 `nosniff`、私有禁缓存及沙箱策略。HTML 等主动内容以下载方式交付。平台附件先检查发送者，再进行受限域名和有界大小的下载；重定向逐次检查，原 API 认证头不传给跳转地址。

## 文件渲染与站内预览

用户上传、Bot 发送和群聊中的文件共用“预览”入口，在当前页面打开文件查看器，支持手机全屏、下载、Esc 关闭及失败重试。较小的 Bot 文本附件直接在聊天中渲染，消息更新保留已经加载的内容。

| 格式 | 查看方式 |
| --- | --- |
| Markdown（md、markdown、mdown、mkd） | 标题、列表、任务勾选、引用、表格和代码块；可切换源码 |
| JSON | 格式化展示，可查看原文；无效 JSON 回退原文 |
| CSV、TSV | 表格展示，支持引号、转义引号、单元格内换行 |
| 文本、日志、代码、XML、YAML、TOML、配置文件 | 等宽源码，识别 UTF-8、带 BOM 的 UTF-16 及常见 GBK/GB18030 中文文本 |
| HTML、SVG | 沙箱视觉预览与源码切换，禁用脚本、导航和外部资源 |
| DOCX、ODT | 正文与表格内容；DOCX 保留常见标题、加粗和斜体 |
| XLSX、ODS | 切换工作表查看单元格内容，不执行公式；显示已保存的值，日期格式可能不同 |
| PPTX、ODP | 按文档顺序切换幻灯片查看文字内容 |
| ZIP | 查看包内目录和文件大小，不执行或解压文件到磁盘 |
| 图片、音频、视频、PDF | 继续使用浏览器原生查看与播放能力 |

预览完全在当前浏览器中处理，无需第三方文档服务或外部账号。Office 是内容预览，复杂版式、图片、图表、宏和旧版 DOC/XLS/PPT 不在该渲染范围内；未知格式、损坏或加密文件仍可下载。Markdown 中的原始 HTML 按文本展示，远程图片不自动加载。

文本预览最多读取 1 MiB，超出时明确提示截断；聊天内自动预览最多读取 120 KiB，保留最多 16 份文本缓存。表格最多显示 500 行、100 列。压缩文件读取上限 25 MiB、目录上限 2,000 项，Office XML 单项上限 2 MiB、合计上限 16 MiB，不提取图片等无关数据。关闭预览会取消未完成的请求；切换文件后旧请求不会覆盖新内容。预览不影响原文件字节和正常下载。

## 社交回复

统一回复包含正文、文件、错误和取消状态。模型失败、任务停止、附件接收失败会有明确反馈；发送平台之前执行密钥脱敏。生成文件不等于平台发送成功，发送失败会记录在「设置 → 社交平台」，并尽力通知使用者。各平台类型与资格限制见[社交平台说明](social-platforms.zh-CN.md)。

社交发送队列持久化逐片进度，服务重启恢复尚未开始的排队片段，确认过的片段不会因普通重试重复发送；不确定发送须先核对再重发或跳过。执行输入、附件引用、检查点及协作结果也可恢复，见[共享账号、事件接入与可靠恢复](accounts-events-recovery.zh-CN.md)。平台断网时仍无法保证错误通知立即送达。当前自动化测试使用模拟平台，没有将真实账号接入验收列为完成。

## 历史、搜索与阅读位置

单聊和群聊均从持久 JSONL 归档分页读取，每页最多 200 条，可向前加载、向后加载或跳到最新。搜索覆盖完整保留历史中的消息文字和附件文件名，并可直接定位到尚未加载的匹配；不包括 PDF 内文、OCR 或所有二进制文件内容。

会话侧栏显示未读数量及「更多未读」入口。页面可见时按实际可见消息更新已读，保存消息锚点和滚动偏移；再次进入或刷新会恢复位置。阅读状态保存在 `<home>/reading.json`，同一服务的多个客户端共享；较旧的已读回执不能让已读进度倒退。它不是独立多用户账号的阅读状态。

新群消息持续归档，不再只依赖 `state.json` 的滚动群日志。首次打开会将旧版本仍保留的群日志归档并去重；旧版本已经从滚动日志删除、且没有在其他归档中保留的消息无法恢复。升级前备份整个数据目录，包括 `chats/`、`media/` 和 `reading.json`。
