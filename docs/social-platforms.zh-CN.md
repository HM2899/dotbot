# 社交平台接入与设置

左侧栏只放 Bot 和群聊。点击左下角个人头像／设置，进入统一设置窗口：通用设置、团队、例行任务、技能、连接与密钥、社交平台、用量、模型与供应商。手机端在顶部横向切换分类，右上角关闭后返回原来的会话。

## 连接平台

在「设置 → 社交平台」选择平台、消息接收 Bot 或群聊，填写凭据并连接。接入支持文字和附件；附件经发送者授权检查后下载，进入目标会话，Bot 生成或协作返回的文件随回复发送。模型失败、取消及附件处理失败会返回明确说明。文件读取方式、大小限制和历史功能见[附件与历史说明](files-and-history.zh-CN.md)。

| 平台 | 配置 | 接收方式与注意事项 |
|---|---|---|
| Telegram | BotFather 提供的 Bot token；可选 API 代理地址 | 主动长轮询。群聊需要 `@Bot用户名`、`/命令@Bot用户名` 或回复 Bot 的消息；不会处理发给其他 Bot 的命令。已有 webhook 需在 Telegram 侧停用后再使用长轮询。 |
| 飞书 / Lark | App ID、App Secret、所属区域 | 自建应用启用机器人，在事件订阅中选择长连接，订阅 `im.message.receive_v1` 并授予发消息权限。Lark 账号选择国际区域。 |
| 钉钉 | Client ID / AppKey、Client Secret / AppSecret | 开发者后台启用机器人并选择 Stream 模式接收消息，配置可使用人员范围。 |
| QQ | AppID、AppSecret；可选沙箱 | 官方 Bot 网关。需在平台开通相应私聊、群和频道事件权限。被动回复受 QQ 的回复时限和条数限制。 |
| 微信 | 保存后点击登录，手机扫码并确认 | ClawBot / iLink Bot 接入，依赖账号开通对应能力；不是普通微信个人号的通用登录入口。扫码用户自动进入允许列表。 |

这些连接均由服务所在电脑主动建立，不需要公网回调 URL。访问外部平台仍需要服务端可用的网络和平台权限。浏览器端页面能联网不代表服务进程能访问平台。

微信按 iLink 返回的 `longpolling_timeout_ms` 调整轮询期限，并留出响应余量；空闲读超时会用原进度立即继续轮询，不进入断线退避。实际连接失败按 1、2、4、8、15 秒重试，最长等待 15 秒。重连从最新已保存游标继续，每批消息处理后才保存游标；这不代表平台到服务端的投递时间或模型回答时间可以固定保证。

## 附件能力

| 平台 | 输入 | 产物回传与限制 |
|---|---|---|
| Telegram | 图片、文档、音频、视频、语音、动画、贴纸 | 使用 `sendDocument` 发送原始文件；群内纯附件仍需回复 Bot 或在说明中提及 Bot |
| 飞书 / Lark | 图片、文件、音视频、富文本中的图片 | 上传图片或文件并发送对应消息；需要应用具备读取消息资源、上传与发送权限；暂不支持的空内容消息会明确反馈 |
| 钉钉 | 消息或富文本中的 `downloadCode` 附件 | 上传媒体后通过机器人 OpenAPI 发送文件；需要机器人具备相应单聊／群聊权限 |
| QQ | 官方消息事件中的附件 | v2 单聊／群聊上传文件后引用媒体；旧频道接口只支持图片回传，其他类型明确反馈；通用文件能力取决于应用资格与平台权限 |
| 微信 | iLink 媒体附件，CDN 下载并解密 | 获取上传地址、加密上传后回传文件；需账号具备 iLink 能力，不是任意微信个人号接入 |

音视频附件可以接收和交给已启用的文件工具，但没有因此自动获得语音转写或视频理解能力。图片和 PDF 可作为模型原生输入，文本提供有限预览，Office 和压缩包需要文件工具处理。平台自己的大小、格式、频率和回复时限可能比项目限制更严格。

## 授权与运行状态

允许的发送者留空时，消息不会交给 Bot；发件人会出现在平台卡片的待授权列表，点「允许」后可发送新的消息。被拦截的旧消息不会自动重放。也可以直接填写平台用户 ID，每行一个，或用 `*` 开放给所有人。

卡片显示连接状态、最近接收／发送时间和回复发送失败原因。允许列表可以展开并撤销单个人的访问。附件下载完成、回复入队及实际发送时都会复查授权；撤销后不继续派发新工作或发送后续内容。暂停会停止连接并取消待确认的微信扫码；恢复后重新连接。Telegram 保存轮询进度，重连时不会重新执行已处理的更新。失败的回复保存在同页的发送队列中，修复权限或网络后可重试剩余片段。

模型失败和取消通过统一结果结构返回平台。平台本身发送失败时，设置卡片会记录脱敏错误，并尽力发出失败说明及网页下载指引；若平台完全不可达，无法保证错误提示仍能送达。待发送回复持久保存在 `outbox.json`，服务重启会补送未开始的排队片段，确认过的片段保留进度。发送中的中断或网络结果不确定会标为 uncertain，必须先核对，再选择重发或「当前片段已收到」。相关执行输入与中断任务可在团队页核对后继续，详见[可靠恢复说明](accounts-events-recovery.zh-CN.md)。平台收件 ACK／游标与执行输入持久化仍有中断窗口，不承诺事务收件箱。

凭据存放在服务端 `<home>/channels.json`，Unix 文件权限为 `0600`，页面只收到遮罩。编辑时保留遮罩即可保留原凭据。微信的登录区域地址和轮询进度也会随编辑保留。接入错误与回复错误会隐藏已配置的通道密钥。

Bot 单聊支持 `/new`、`/reset` 开始新对话，以及 `/stop` 停止当前工作；目标为团队群聊时 `/stop` 停止该群的工作。

## 验证范围

```sh
cargo build
node dev/channels.e2e.mjs
node dev/attachments.e2e.mjs
node dev/integrations.e2e.mjs
DOTBOT_CHROME=/opt/google/chrome/chrome node dev/ui.e2e.mjs
```

接入测试使用本地模拟 Telegram 和微信服务，覆盖图片／PDF 输入、直接和协作文件回传、模型失败与取消、微信 CDN 加解密及上传 MD5，以及授权、群聊定向、重复更新、重连进度、暂停、发送错误、密钥遮罩、扫码确认与取消。Rust 媒体测试验证飞书／钉钉／QQ 的 multipart 上传与媒体引用，以及下载跳转校验和认证头不向重定向地址转发。界面测试复用一个浏览器检查设置导航、文件上传、历史与未读、配置保存和移动端布局。这些测试不登录真实账号，也不验证各平台当前的账号资格或运营限制。
