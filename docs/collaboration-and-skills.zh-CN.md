# Bot 联动与共享技能

所有 Bot 的回复、进度、追问、协作总结和记忆摘要统一使用简体中文，不随界面语言、旧会话或英文技能切换。英文资料和工具回执先理解再用中文归纳；代码、命令、路径和标识符保留原文。仅用户明确要求的翻译或外语正文使用指定语言，其余说明仍用中文。

侧边栏顶部「＋ → 新建分组」可将助手和群聊放在同一分组。分组标题可折叠，右侧「⋯」可重命名、调整会话归属或删除分组；删除只移除分组，会话保留并回到未分组。助手和群聊详情、新建会话时也可选择分组。分组与折叠状态重启保留，搜索会临时展开匹配项；置顶助手仍显示在顶部。整理分组不改变模型、权限或任务状态。

群聊会检查保存会话的模型、服务商、工作目录等配置，旧版未记录配置的群成员会话首次调用时自动重建，以避免继续使用已下线的旧模型。恢复会话出现“模型不支持”或“找不到会话”且尚未执行工具时，只以原 Bot 的设置重建一次，并恢复群聊上下文与附件；不会改用其他模型或重放已经执行的工具。失败、停止的群消息不会提前标记为已处理；群轮次保留真实失败原因，部分成员成功也不会掩盖其他成员的失败。相关验证见 `dev/groups.e2e.mjs` 和 `dev/groups-ui.e2e.mjs`。

主 Bot 和“自动协作”群聊可以直接接收目标，无需用户逐个指定或手动委派。执行前，系统用“回复前规划”模型（默认用供应商的默认模型，可在“设置 → 模型与供应商 → 后台任务的模型”指定一个更快的模型）根据成员职责、说明、相关已启用技能、权限和当前任务量规划分工；每次可选择最多四个不同 Bot 处理互不依赖的工作，同时执行并以普通聊天消息返回。每个 Bot 的私聊、群成员会话和独立委派任务共用一个执行名额；排队的用户请求优先于其他 Bot 的更新和后台工作，同类消息按入队顺序处理。任务进行中发来的新消息交给正在工作的 Bot 自行判断如何处理（见下文）。依赖前置结果的工作在收到结果后继续。简单问题、明确要求独自完成、缺少合适成员时直接处理。每个 Bot 执行任务和回复时始终使用自己设置中的模型和权限；选技能、找经验、分配任务这三步回复前规划并行进行，使用更快的规划模型，以缩短开始回复前的等待。

用户明确要求“委派”（或 `delegate`）时，系统先按职责、相关技能、权限及任务量选择合适的现有 Bot，保持其模型、推理强度、权限、技能与工作目录设置不变；只有没有合适对象时才新建并启动专属 Bot。主 Bot 和普通 Bot 的私聊均支持；群聊由管理员（无管理员时首位成员）统一委派，同等适合时优先群内成员，选中的群外 Bot 自动加入当前群组，任务在群内执行，结果返回原会话，不读取成员私聊。这一明确要求优先于群聊的自动／管理员／全员模式，不会重复派发。新 Bot 继承发起者的模型、推理强度、权限、优先技能及有效工作目录，不自动成为主 Bot，也可在后续合适的任务中复用。同一持久请求的重试复用已创建的 Bot 和回执；协作者及结果回传不会递归委派。选择失败、超时或返回无效对象时明确报错，不以此为由新建 Bot。拒绝委派、引用示例、附件中的指令或解释委派机制不触发；只读权限仍禁止创建与委派。停止原会话也会停止关联任务。

群聊默认采用“自动协作”：管理员（未设置时为首位成员）协调，仅在群成员中选人。任务在成员的群内会话执行，成员结果和协调 Bot 的汇总直接显示在原群聊，不写入成员私聊。旧版默认“管理员回答”群聊首次启动时升级为自动协作；可在群聊详情中切回管理员回答，或选择全员依次回答，之后保留选择。`@名字`、`@all` 继续按明确指定执行。

执行过程中，Bot 也可通过 `list_bots` 和 `message_bot` 交接后续发现的独立任务，避免重复分配已自动派出的工作。协调 Bot 保留汇总和验收责任，未收到结果时不能声称任务完成。

任务进行时直接发送消息即可，不需要选择“纠正”或“新任务”：消息会交给该会话中正在工作的 Bot（主 Bot 只有一个委派任务时交给执行者；在执行 Bot 的私聊中交给它正在处理的任务），由它自行判断——是对当前任务的补充、修改或纠正，就按最新要求继续同一任务，保留任务编号、原始附件、会话、模型、操作检查点和结果回传位置；是无关的新请求，就先完成当前任务再处理，并在回复中分别交代；判断不了时按补充处理。发送时如果该任务恰好已结束，消息会自动作为新消息发送，不会丢失。排队的委派任务也能收到追加消息，不打断执行者正在处理的其他任务。追加消息会撤销旧执行中尚未确认的操作审批，避免之后误执行旧指令；它不撤销已完成的外部操作，执行者应先核对检查点，避免重复执行。会话右上角“更多”菜单可以“清除聊天记录”：删除该会话（群聊含各成员席位）的全部消息并重新开始模型上下文，记忆、任务和文件保留；正在处理任务时不能清除。

图片或视频生成时，提示词、负面提示词、API 请求体和内部参数仅用于工具调用，不作为用户可见的进度文字、附件说明或最终回复。识别为生成媒体的请求通过工作状态报告进度，暂存模型草稿；工具调用后的最终回复会检查实际使用的提示词、生成参数及提示词标签。图片和视频的服务商错误均不会原样回显内部参数。生成媒体不把提示词填入说明，旧版本生成文件的提示词说明也会在聊天、状态和 API 输出时剔除。服务端保留工具诊断记录；这些工具记录不广播到聊天。验证使用本地图片／视频服务，不能替代真实生成服务的质量验收。

交接可以包含 `context`（相关事实与限制）、`expected_output`（交付物及证据）、`acceptance`（验收条件）和 `files`（当前会话中的附件引用）。省略 `files` 时继承当前任务附件；传入列表时只分享选中项，空列表不传附件。带初始任务的 `create_bot` 同样支持。多级委派保留父任务实际获得的输入，不恢复已排除的文件。接收方不能直接读取委派者的私聊和 Docker 文件。工具返回任务编号；结果和产物自动回到请求会话，不需要轮询。`list_tasks` 用于主动检查或恢复任务，只显示当前会话请求的任务及分配给当前 Bot 的任务。

多层协作返回结果时会保留任务编号、原始要求和父任务关系，继续检查循环委派。同样内容在不同父任务下分别计账，避免结果串用。团队设置中的任务列表显示实际委派者、协作链、状态和结果。

停止父任务会停止它派生的任务。聊天中的停止按钮在协作者仍工作时也会保留；停止该聊天会停止其关联的协作。其他独立用户请求继续保留在 Bot 队列中。已执行的外部操作不会被停止操作撤销。

## 共享技能

在“设置 → 技能”中搜索名称或使用场景，展开查看流程，编辑、启用或停用技能。中文名称保留为显示名称，底层自动生成稳定标识。流程模板包含目标、输入、前置条件、步骤、验证、异常恢复和交付物；根据实际任务补充内容，未测试的步骤不能标为已验证。

Bot 通过 `list_skills` 搜索元数据，再通过 `read_skill` 或 Skill 工具读取匹配技能。技能可以说明如何委派及检查协作成果，但不授予额外权限。只读 Bot 可以查询和读取技能，不能修改。

新建技能可直接使用 `save_skill`。更新时先 `read_skill`，将返回的 `revision` 传给 `save_skill`。Bot 对已有技能的保存只生成候选草稿，不立即替换正式版本；设置中可查看完整草稿并运行对照评测。用户在设置中直接编辑仍按显式编辑保存。如果其他 Bot 或用户已修改该技能，旧版本保存会被拒绝；读取最新内容并合并后重新保存。网页发生冲突时保留当前编辑内容，可复制后取消编辑、重新打开最新版本再合并。

启用的技能位于 `<home>/plugin/skills/`，每轮作为插件加载。停用时整个技能目录移到 `<home>/disabled-skills/`，附属资源一并保留；编辑不会自动重新启用。启停对后续轮次生效，不会取消已经执行的任务。


## 用命令安装技能

技能页的技能商店上方有“用命令安装”输入框，终端里可用 `dotbot skill install`。两者共用同一套解析和校验：

```bash
dotbot skill install npx skills add owner/repo --skill name   # 直接粘贴 npx 安装命令
dotbot skill install owner/repo@name
dotbot skill install https://github.com/owner/repo/tree/main/skills/name
dotbot skill install owner/repo/skills/name
dotbot skill install ppt-generator                            # 商店技能名称或 ID
dotbot skill install ./my-skill                               # 本机文件夹（仅终端）
dotbot skill list
```

- 粘贴的命令只用来读取来源，不会被执行；安装也只复制文件，不运行其中的脚本。
- 仓库里有多个技能时需要用 `--skill` 指定，错误提示会列出可选名称；不写分支时使用仓库的默认分支。
- 指向商店已收录技能的命令（如 `anthropics/skills --skill pdf`）按商店条目安装，保留固定版本和来源记录。
- 隐藏文件（如 `.git`、`.github`）不会被安装，包含链接或子模块的来源会被拒绝；文件数量和大小限制与商店安装一致。
- 网页不能安装本机文件夹，请在终端操作。服务运行时用终端安装的技能，刷新页面后显示，Bot 从下一轮开始可以加载。
- GitHub 匿名访问每小时约 60 次请求，每个文件计一次；设置环境变量 `GITHUB_TOKEN` 可提高限额。

## 自动获取技能与各 Bot 的专长

实际任务开始前，Bot 使用自己设置的模型选择最多 3 个相关的已启用技能，优先考虑其优先技能与以往加载记录。简单问候与单纯接收协作者结果不会触发此准备流程。准备失败或超时后继续执行任务，Bot 仍可通过技能工具自行处理。

没有合适技能时，Bot 可以从公开目录导入，也可以按自身职责和任务编写一个具体、可复用的技能；导入失败时尝试使用该轮生成的备用流程。新流程直接放入当前轮的上下文，不必等下一条消息。流程要求包含有用的方法、输入参数、可用工具、前置条件、产物检查和有限的失败恢复；不会修改 Bot 的模型或权限。只读 Bot 可以选择已有技能，不能导入或编写。

公开目录目前是精选的官方 `anthropics/skills` 仓库条目，覆盖 PDF、Word、表格、演示文稿、前端设计、网页测试、MCP 开发、技能编写等场景，并非全网技能市场。导入通过 GitHub API 固定树和文件版本，完整保留该技能的脚本、参考资料、素材和上游许可通知；路径、链接、文件数量和大小受限，失败的下载不会发布半份技能。安装不执行脚本、不安装系统软件，执行时仍需使用 Bot 已获准的桌面或本地终端工具。网络不可用、API 限流或资源超限时可编写适合当前环境的流程。

“设置 → 技能”只管理已安装技能及新建流程，不再展示公开技能目录或手动导入入口，打开页面也不请求公开目录。已安装技能仍可查看来源、编写 Bot、未验证标记和加载过的成员；Bot 按任务自动获取或编写技能的能力保留。Bot 的聊天详情中打开“技能专长”，勾选优先技能并查看其加载次数。技能库仍然共享，各 Bot 分别维护选择偏好和加载记录，自动分工参考相关流程与职责，而不会把加载次数当作能力评分。技能档案保存在 `<home>/skill-profiles.json`，重启后保留。

新编写和导入的技能均标记为 `untested`。`prepared` 只表示已加载，`turn-completed` 仅表示这一轮正常结束，不证明流程或交付物通过质量验收。Bot 必须实际检查产物，依据证据改进技能，不可凭创建成功就宣称任务完成。停用技能不会被自动覆盖、重新启用或用同名导入替换。

工具调用顺序：`find_skills` 查找已有技能与公开来源 → `install_skill` 导入（或 `save_skill` 编写）→ `read_skill` 读取并在当前轮使用。`read_skill_resource` 按相对路径读取配套资料；文本直接返回，二进制或大型资源返回当前会话附件引用，通过获准的接收文件工具送到执行环境。先检查脚本再执行，不允许相对路径越界或符号链接读取。

`dev/skills.e2e.mjs` 使用本地来源服务和模型夹具验证：不同 Bot 自动编写与复用、当前轮应用、完整资源导入、来源失败回退、只读/停用/停止保护、群聊与模型保留，以及重启持久化。这些测试不代表付费模型编写的真实流程质量已经验证。

## 学习循环

参照 [Hermes Agent](https://github.com/nousresearch/hermes-agent) 的学习循环：学到的东西以技能和记忆的形式写下来，不训练或修改模型参数；默认不额外调用模型。

- **技能**：Bot 完成较复杂的任务（约 5 次以上工具调用，或踩坑后才找到办法）时，在同一轮里用 save_skill 把可复用的流程写成技能，或修补本次用过、但已过时/不完整/有错的技能。用哪个技能由 Bot 自己决定，界面不再提供手动指定。Bot 自己写的技能直接修补，带版本校验：过期版本不能覆盖新内容，停用的技能不能改，改坏了可在“设置 → 技能 → 版本与回滚”恢复。导入的或用户编写的技能，改动先存为候选，对照测试通过后才替换。
- **记忆**：一句话能说清的环境事实、约定和教训用 remember 记下，在后续会话开头随记忆一起提供。
- **会话搜索**：需要以前的工作时，Bot 用 search_history 搜索自己的私聊和所在群聊（搜不到其他 Bot 的私聊），按需检索，不预先注入每轮。
- 简单问答和一次性操作不沉淀；只记录本次确实验证过的做法；不保存凭据和一次性私人细节。

### 整理员（Curator）

整理员默认关闭，可在“设置 → 技能”打开。打开后系统在空闲时（没有 Bot 正在执行或排队任务）额外调用模型回看已完成的任务：目标、完成或失败状态、检查点、工具结果和所用技能，提炼最多 3 条“适用条件 → 具体方法”的经验，每条关联实际工具动作或结果编号；只有 Bot 自述的结果标为“未独立验证”，失败任务不能被写成成功案例。默认在任务结束 20 秒后开始，每个 Bot 优先检查最近 30 条记录，并逐步补看历史任务；每次 20 秒超时，最多尝试 3 次，有新任务时让出。每个任务多一次模型调用，开销较大。

整理出的经验在后续任务中按中英文概念与文本相似度在本地选出最多 4 条放入提示，不调用模型；按 Bot 和原会话隔离，私聊经验不带入群聊，群与群之间也不互相读取；相同条件的新方法替代旧方法。

当一条改进得到所用技能、精确版本和已确认的终端或浏览器执行记录支持时，整理员创建独立的候选技能包（保留正文、脚本、资源和许可），在原 Bot 的模型和权限下对所有保存用例分别运行冻结的基线与候选版本；每个阶段用独立会话和项目副本。全部通过验收并附实际检查或执行证据才替换正式技能；失败动作、缺失证据、模型/权限/环境变化、项目输入差异及并发编辑都会阻止发布。候选可查看或弃用，每个技能最多 3 个待处理候选，最多保留 100 个候选记录。记录保存在 `<home>/learning.json`，重启保留。关闭整理员后不再生成新的整理记录和自动评测，已启动的评测按回执完成。

`dev/inline-learning.e2e.mjs` 验证默认学习循环：不产生额外的整理或经验筛选调用、Bot 技能的就地修补与版本校验、用户技能仍走候选、search_history 的范围。`dev/learning.e2e.mjs` 验证整理员：实际终端记录 → 经验 → 技能候选 → 后续复用、失败及取消任务、私聊与群聊隔离、用户并发修改优先、前台任务抢占、历史补看与重启去重。推理内容使用模型夹具，不代表真实模型生成的每条经验都已通过质量评估。


## 基于实际表现的分工

任务详情保存选择时的指标，Bot 详情显示当前设置下的表现。旧记录未保存执行设置时不补造评分。模型或权限改变后旧样本仍保留，但不再作为当前设置的能力指标。统计是分工参考，不保证未来任务成功。`dev/routing-learning.e2e.mjs` 覆盖技能测试记录参与分配、模型变化、冻结版本对照及坏产物阻止发布；`dev/routing-learning-ui.e2e.mjs` 覆盖中文候选界面和手机布局。


## 简化后的聊天与任务

不再提供并行任务操作、费用统计和预算设置。聊天顶部不显示任务指派横幅，聊天中不再生成统一验收或交付结果卡片；委派完成或失败后按普通消息返回，文件仍作为普通附件。任务停止和当前任务纠正继续可用。技能的内部对照检查保留在设置中，不向聊天插入报告。
## 派发后释放执行占用

主 Bot 成功发布当前批次任务后结束派发轮次，不占用自己的执行名额等待协作者。自动分派成功后不额外调用主模型生成等待说明；工具循环中成功的 `message_bot` 或带初始任务的 `create_bot` 可结束本轮。混合工具批次仍处理其他必要结果；派发失败不能伪装成功或提前结束。

未完成的协作任务继续保留在任务记录中，支持查看和取消，但不会单独使主 Bot 显示忙碌或计入工作中的 Bot 数量。用户的新请求可正常执行；协作回复经既有持久回传链路进入主 Bot 队列，处理时才重新占用名额。停止后的迟到回复仍遵循原有取消规则。

回归检查：`node dev/handoff.e2e.mjs` 使用隔离服务和模拟模型，覆盖自动派发、手动派发、等待期间的新请求、结果唤醒及前端状态；不调用真实付费模型，也不启动浏览器。
