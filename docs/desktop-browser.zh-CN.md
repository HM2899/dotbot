# 桌面浏览器与软件

默认模式下，同一团队的所有助手共用一个持久的 Docker 电脑。安装的软件、命令行环境与 `/config` 文件共享，每个助手拥有独立屏幕、鼠标键盘焦点和会话总线，可同时操作不同窗口。屏幕不隔离文件或凭据，修改共享文件或安装软件前仍需协调。对话中的“打开浏览器”“访问网站”“使用软件”均指该桌面内的应用，网页面板展示的也是这个桌面。

打开会话的工作区，可输入网址，或者点击“浏览器”“文件”“终端”。这些按钮会先接管桌面再打开相应应用，助手暂停会干扰你的桌面操作。完成登录或操作后，点击“交还”，助手继续使用同一画面。登录状态保存在全队共用的浏览器配置中。

助手通过 `desktop_browser` 打开桌面浏览器，再用桌面截图、点击、输入、按键等工具继续操作；软件启动仍使用 `desktop_open`。只读权限禁止这些变更操作，用户接管时也会拒绝助手的变更请求。本机终端协作仍仅包含终端与文件能力。

网址栏接受 HTTP/HTTPS 地址，也接受省略 `https://` 的域名；不接受带账号密码的网址及脚本、文件协议。应用快捷入口限定为浏览器、文件和终端，不把用户输入当作启动命令。启动失败会显示错误，桌面连接失败时可直接重试。

桌面模式不会启动独立 Playwright 浏览器，也不会向模型提供独立浏览器 MCP。原有独立浏览器的配置和 Cookie 不会自动迁移到桌面浏览器。请在桌面中完成需要的登录。

Docker 不可用时会显示桌面不可用，启动 Docker 后需重启 dotbot。只有显式指定 `--no-desktop` 才使用兼容的独立浏览器模式；`--browser-command`、`--headed`、独立浏览器共享 Cookie 及原浏览器录制入口属于该兼容模式；云端桌面有自己的示范教学入口。

验证：`cargo build` 后运行 `DOTBOT_CHROME=/opt/google/chrome/chrome node dev/desktop.e2e.mjs`。测试创建独立的临时桌面容器，使用容器内本地网页检查真实浏览器、桌面接管与移动布局，结束后清理测试容器和浏览器，不操作现有助手桌面。


在「桌面与应用 → 桌面示范教学」开始示范后，系统接管 Bot 桌面，记录远程画面上的点击、拖动、滚动、按键和应用启动。输入值与剪贴板内容不录制，以参数占位。完成后交还桌面，填写任务用途并保存；Bot 将示范整理为包含前置条件、参数、可见检查点、失败恢复、权限边界和验收步骤的技能。坐标只帮助理解示范，执行时必须重新识别布局。录制最多 500 步，服务重启前应保存或取消尚未提交的示范；录制本身不是未来执行成功的证据。

云端项目放在协调 Bot 的 `/config/workspace`。委派终端操作在各任务的桌面副本中进行，最终合并与检查也在云端完成，无需启用本机终端。桌面软件仍共享该 Bot 的同一张画面，用户接管时 Bot 的图形操作被阻止。本机不提供图形界面录制或操作。


共享电脑的数据位于 `<home>/desktops/shared`，屏幕编号保存在 `screens.json`，服务与容器重启后保持不变。删除助手只关闭其屏幕和通过桌面启动器启动的应用，不删除共享电脑或文件；关闭 dotbot 时只停止本团队的共享容器。

首次启动会检查同一团队、同一基础镜像的旧桌面，按容器写入层大小选择迁移源，将其软件层保存为迁移镜像，复制其主目录而不覆盖新目录已有文件。迁移完成后旧容器可删除。旧 Bot 目录保留在主机 `desktops/bot-*`，但不再挂载进共享电脑，避免在文件对话框中显示为一堆磁盘；仍挂载旧目录的共享电脑会在下次停止后启动时保存软件快照并去掉这些挂载。迁移不会合并不同旧容器中互相冲突的软件安装。正在安装软件时延后迁移，记录位于 `migration.json`。基础镜像须兼容 LinuxServer XFCE、Xvfb、DBus 与支持 Unix socket 的 Selkies。

## 共享浏览器

全队只有一个 Chromium 进程和一份浏览器配置（`/config/.teambot/browser`），没有逐 Bot 的浏览器配置，也没有登录同步服务。任何 Bot 或用户登录、退出，其他 Bot 立即看到同样的状态。

浏览器显示在打开它的那个 Bot（或用户）的桌面上，不再有单独的共享屏幕。一个 Bot 可以开多个标签页，但同一时刻只做一项浏览任务。另一个 Bot 用 `desktop_browser` 或工具栏打开浏览器时：若当前持有者正在工作或被用户接管，会先等待（最多约两分钟，可被停止或更正打断）；否则关闭原窗口（Chromium 正常保存会话），用同一配置在新 Bot 的桌面上恢复原有标签页。操作仍使用桌面截图、点击、输入等工具。

同一个网站账号会被多个 Bot 使用，退出登录会影响全队；提示词已要求 Bot 不擅自退出或切换账号。升级后首次打开会以最近使用过的旧逐屏幕配置为起点，旧目录保留不动，旧同步守护进程会被停止。

## 共享资源协调

`desktop_run` 自动识别包管理命令及命令中可见的 `/config` 绝对路径，一次保留所有相关资源；同一或上下级路径互斥，不同项目仍可运行。动态计算的文件名须通过 `resources` 明确声明；未声明且无法识别路径的命令保守保留 `/config`，明确声明可缩小等待范围。`desktop_open` 对文档路径的保留持续到本轮结束。跨多个操作编辑时，先用 `desktop_resource` 一次申请所需路径，保存并关闭文档后主动释放；任务结束、停止或更正时也会释放。

等待最多两分钟，可被停止或更正打断。正在执行的受管命令会用独立进程组和随机标记识别，停止时仅终止该命令组，再释放资源；不会终止其他屏幕或用户窗口。协调作用于受管工具操作，无法解析任意 shell 中动态路径，也不拦截用户在 GUI 中的手工编辑。软件自身的文档锁仍有效。不会新增并行任务操作面板、指派横幅或费用界面。

`node dev/desktop-resources.e2e.mjs` 检查实际共享文件互斥、独立项目继续执行、取消等待与运行命令，以及升级时保留可见浏览器 PID、容器和用户接管。所有资源和浏览器均在测试专属容器中清理。
