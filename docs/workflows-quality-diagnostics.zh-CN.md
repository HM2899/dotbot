# 任务、技能检查与平台诊断

不同 Bot 可同时执行；同一个 Bot 的私聊、群成员会话与独立委派共用一个执行名额。空闲时优先处理排队的用户消息，再按入队顺序处理后台协作更新。各 Bot 保留自己的模型、权限、记忆和工作目录，普通委派完成或失败后以聊天消息返回；附件继续传回原会话。聊天顶部不显示任务横幅，聊天内不再生成统一验收、项目报告或交付卡片。费用统计、预算设置、任务暂停和优先级操作已移除。

停止会取消对应任务与派生任务，保留无关的排队消息。任务进行中发送的消息会交给正在工作的 Bot，由它判断是补充当前任务（继续使用原始附件与最新要求）还是另一个新请求（完成当前任务后再处理）。停止不会撤销已经发生的外部写入、发送或提交；中断后先核对实际状态。

## 技能检查

设置中的技能测试、候选改进和版本回滚保留。技能包版本覆盖正文、脚本和资源，资源变化会使旧版本写入请求失效。完整包校验检查路径、大小、符号链接、脚本语法和 JSON 结构，不直接执行脚本。

试运行保存任务与检查条件，对照测试使用冻结的基线和候选，在原 Bot 模型、权限和相同项目输入下依次执行。实际文件检查和工具证据通过后才替换正式技能；模型或环境变化、文件损坏、缺失证据以及用户并发编辑都会阻止替换。测试项目副本不合并回原项目。技能测试记录只在设置中查看，不向聊天追加报告卡片。

## 社交平台诊断

设置中的平台延迟诊断保留接收附件、排队、模型执行与发送等阶段时间。计时从本服务收到消息开始，不包含平台把消息送到本服务之前的耗时。模拟平台检查不能代替真实账号收发验收；测试不会擅自向用户联系人发消息。
