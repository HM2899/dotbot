# Grokbot 功能差距审计

审计日期：2026-10-24。最初采用 dotbot 源码静态链路检查；下方同日进度补充后续实现与模拟服务、浏览器、隔离进程重启验证。未调用真实模型、发送外部消息或重启用户服务。这里区分项目已确认的缺口、第三方介绍中的对齐方向，以及截图只能证明存在入口的功能，不宣称已取得官方完整规格。

## 2026-10-25 本轮优化

后续已按用户要求移除并行任务调度操作、费用统计与预算、顶部任务横幅及统一验收和交付报告。当前模型调用依次执行，普通委派仍会回传消息和附件，技能检查放在设置中。下文为历史审计记录，不代表所有旧功能继续保留。

## 前四项处理进度（同日更新）

用户选择的前四项现已实现：统一包含正文／文件／错误／取消的回复；五个平台的附件收发路径与协作产物回传；单聊与群聊完整保留历史分页、搜索、未读及阅读位置；网页通用文件上传及群聊附件。文件权限、原生模型输入、失败重试和手机界面已有回归检查。详见[附件与历史说明](files-and-history.zh-CN.md)与[社交接入验证范围](social-platforms.zh-CN.md)。真实平台账号权限仍需实际账号验收。

## 第五至七项处理进度（同日更新）

用户选择的第五至七项现已实现。第 5 项增加 Gmail、Calendar、Drive、GitHub、Microsoft 365 共享 OAuth 目录、scope、PKCE、续期、暂停／撤销、真实 API 测试，以及自定义 MCP 协议测试。第 6 项把公网地址、签名密钥、平台步骤、本地诊断与到达证据放入设置，GitHub 可注册、测试、查询和删除 hook；Slack／Teams 仍按指引配置外部平台。第 7 项保存执行输入、检查点和动作回执，提供中断后核对继续、协作结果补交、持久社交发送队列及逐片重试／不确定结果核对。

详见[共享账号、事件接入与可靠恢复](accounts-events-recovery.zh-CN.md)。验证使用本地 OAuth／平台模拟服务和实际隔离服务重启，不冒充真实账号验收；不承诺平台全局 exactly-once、事务收件箱、模型内部指令级恢复或任意 MCP 的自动 OAuth。

下方缺口表与“其他体验差距”保留为**修复前的审计快照**，其中前七行及未读条目不再代表当前实现。语音、技能版本、浏览器完整登录共享和跨设备终端等未选项目仍保留原边界。

## 判断

团队助手的核心结构已经存在：具名专业 Bot、Chief、独立指令和记忆、自动委派及文件回传、群聊、独立持久电脑和浏览器、接管、共享技能、定时和事件任务、共享 MCP 与密钥、手机网页。差距主要集中在账号接入、消息和附件的完整链路、历史与未读体验，以及运行可靠性。继续增加菜单或只改提示词无法补齐这些链路。

## 修复前：优先处理的实际缺口

优先级按当前项目的用户影响排列，不表示已验证 Grokbot 官方具备下表全部功能。

| 优先级 | 缺口及当前证据 | 用户遇到的情况 | 补齐标准 |
|---|---|---|---|
| P0 | 社交回复只传文字。`src/channels.rs` 的 `Incoming` 没有附件；`src/team.rs` 的 `Sink`、`Inbound.done` 只传字符串，生成文件没有随平台回复发送 | 在微信或 Telegram 要求生成 PDF，网页可能有文件，平台聊天收不到对应附件；发来的图片/文档也没有通用下载处理链路 | 定义包含状态、文字、文件的统一消息；实现各平台媒体下载、权限校验、发送和不支持类型的明确反馈 |
| P0 | 失败信息没有完整返回社交平台。`Team::turn` 失败时把 `answer` 置空，`channel_message` 丢弃空回复；网页中的错误 notice 没有通过该回调返回 | 模型执行失败或任务被停止后，平台使用者可能一直等回复 | 结构化返回完成、失败和取消；平台获得可理解且脱敏的结果，区分模型失败与平台发送失败 |
| P0 | 历史分页未接到 UI。`web/app.js` 的 `open` 仅调用一次 `chat.page`，没有使用 `more`；`searchConversation` 只搜索 DOM。`Team::page` 私聊每次 200 个非工具条目，群聊最后 300 个条目且 `more` 固定为空 | 重新进入长会话，早期记录无法继续加载，搜索也找不到未加载的内容；这不等于全部历史已从磁盘删除 | 私聊和群聊均可向前分页，搜索完整保留历史，返回会话时恢复阅读位置 |
| P1 | 网页通用文件输入缺失。`web/index.html`、`attach`、`Team::send_with` 仅接 PNG/JPEG/GIF/WebP，最多 8 张，每张约 5 MB；群聊还拒绝图片 | 无法直接上传 PDF、Word、Excel、ZIP 让团队处理；生成文件可下载不代表用户文件可上传 | 通用附件上传、大小和类型校验、消息内文件引用、Bot 接收和跨 Bot 授权传递；群聊明确附件权限 |
| P1 | 账号连接依赖手配 MCP。`src/connections.rs` 仅保存 stdio/http 配置并检查基本字段 | Gmail、日历、Drive、GitHub 等可以借 MCP 或浏览器访问，但没有本项目统一的账号授权、权限范围、续期、撤销及真实连接测试流程 | 提供常用连接目录、账号授权与状态管理、连接测试；所有 Bot 共享授权，按任务控制实际使用权限 |
| P1 | 事件能力与平台配置尚未闭环。`src/triggers.rs` 有 GitHub/Slack 验签与筛选，Teams 使用 Workflow webhook；外部 App、事件订阅和公网地址仍需手工配置 | 创建了任务不代表 Slack 或 GitHub 的事件真的会到达；Slack/Teams 事件支持也不等于已支持双向聊天 | 设置内完成平台连接、目标选择、订阅指引、真实测试事件和订阅状态展示；不把本地保存成功显示为端到端成功 |
| P1 | 只有连接重连，没有完整持久消息投递与任务恢复。`Tasks::open`、`Routines::open` 把重启时未完成任务标记为中断；社交待回复依赖内存回调 | 服务重启后正在进行的工作不会从检查点继续，平台回复没有持久发送队列；连接恢复不保证旧回复补送 | 保存任务检查点及待发送消息，提供可见重试、幂等去重和中断恢复入口；涉及外部副作用的操作先核对，避免盲目重放 |

## 修复前：其他体验差距及边界

1. **未读和跨端阅读状态。** 截图有“更多未读消息”入口；当前有会话时间、摘要和跳到最新按钮，但没有持久化的逐会话已读位置、未读数量与跨端同步。应在现有会话侧栏完善这些状态，保留用户要求的“管理配置放设置”。
2. **语音。** 截图可见麦克风入口；当前网页没有录音、语音识别、语音合成链路。微信读取上游已有的语音转写文本，不等于项目提供完整语音能力。截图不足以证明 Grokbot 的语音模式、模型或支持平台。
3. **技能教学和管理。** 已有浏览器动作录制并交给模型编写技能；不是完整 Docker 桌面或跨应用示范录制。`Skills::save` 覆写同名技能，尚无版本、回滚、试运行与评估后发布。截图有“市场”入口，但未核实官方市场的安装、分发和审核机制，不应只放一个空入口表示完成。
4. **共享登录的覆盖。** `Browsers::share_from/apply_shared` 共享 cookies，没有同步 localStorage、IndexedDB 等完整站点状态；依赖这些数据的网站不一定能一次登录全队使用。独立浏览器和 Docker 桌面浏览器也有各自登录状态。
5. **持续运行与手机使用。** 已支持在常开服务器部署，关闭访问网页不会停止服务任务；关掉运行服务的电脑则无法继续执行。尚无项目自带托管环境、移动账号体系、后台推送和离线客户端。不能把这些写成“没有后台任务”。
6. **用户电脑与服务端的终端桥接。** `src/local_computer.rs` 直接在 dotbot 服务进程所在电脑启动 Bash。当前开关满足同机终端协同；若服务在云端，尚无经过设备配对、身份认证的用户电脑终端连接器。后续扩展仍应只提供终端与文件能力，遵守用户不需要本机图形界面的要求。现有执行方式不是交互式 PTY，长驻会话也未提供。
7. **提示词存在能力描述冲突。** `prompts/agents.json` 的开发 Bot 模板要求“只操作自己的电脑”“编辑前检查远程桌面”，与已启用的共享本机终端存在冲突；`prompts/team.md` 的“local /config paths”容易混淆本机和容器路径。应按 Docker、浏览器、本机终端实际开关注入统一说明，并要求以真实附件交付、准确报告失败。改提示词本身无法实现 OAuth、附件上传或消息重试。

## 与截图及运行版本的关系

当前源码已有三栏工作区、会话分组、紧凑气泡、协作回执与设置内的管理分类；这些属于已有实现。截图中的未读状态、语音和市场入口则需要相应能力支持，不能仅靠视觉复刻。
